# Awesome Multi-Agent Workflows [![Awesome](https://awesome.re/badge.svg)](https://awesome.re)

> A curated directory of **multi-agent workflows** — the frameworks, platforms, protocols, and research for getting multiple AI agents to work together — as of **September 2026**.

Single-agent frameworks are out of scope: every entry here is about **collaboration** — crews, swarms, supervisor teams, debates, handoffs, and the protocols and durable infrastructure underneath them.

> **Scope:** This list is about multi-agent teams *as working systems*. Single-agent frameworks are out of scope; every entry concerns collaboration — crews, swarms, supervisor teams, debates, handoffs — and the products and infrastructure that run them: commercial/SaaS platforms, cloud multi-agent services, and durable execution infrastructure (retries, checkpoints, human-in-the-loop). For the underlying *coordination mechanisms* (protocols, memory systems, orchestration frameworks in depth, research papers), see [awesome-AI-agent-orchestration](https://github.com/awesome-llms-labs/awesome-AI-agent-orchestration); for the wider single-agent ecosystem, see [awesome-ai-agents](https://github.com/awesome-llms-labs/awesome-ai-agents).


**Verification confidence:** every entry is stamped ✅ **verified** (facts checked on the official docs, repo, or paper page) or ⚠️ **unverified** (third-party or ambiguous). **Capabilities and licenses are never guessed** — if the official source is ambiguous, the entry says so. Machine-readable records live in [`data/multi-agent-workflows.json`](data/multi-agent-workflows.json) with a `verified` boolean per entry. **88 of 89 entries verified** on official sources (2026-09-29).

## 2026 Highlights

- **Agent-to-agent protocols grew up:** A2A hit v1.0.0 as a Linux Foundation project (March 2026), IBM's ACP merged into it (Aug 2025), and the MCP spec's 2026-07-28 stateless redesign moved it under the Agentic AI Foundation. The split is clean: **A2A is agent-to-agent, MCP is agent-to-tool**.
- **AutoGen is in maintenance mode** — Microsoft points new framework users to the Microsoft Agent Framework, while Magentic-One remains the research showcase for orchestrator-led teams.
- **Big-cloud multi-agent is GA:** Bedrock's supervisor/collaborator pattern, the Gemini Enterprise Agent Platform (Vertex AI Agent Engine rebranded), Microsoft Foundry (Azure AI Foundry renamed) multi-agent workflows, and Agentforce orchestration are all production offerings.
- **Durable execution is the substrate:** Temporal's official OpenAI Agents SDK integration, Trigger.dev v3 (Apache-2.0, relaunched Sept 2025 with an AI-agent focus), and DBOS are all courting agent workloads — because agent teams need retries, checkpoints, and human-in-the-loop that survive restarts.
- **License watch:** Inngest is SSPL, Windmill is AGPL-3.0, n8n is fair-code (Sustainable Use License), Restate's runtime is BSL-1.1 — none of these are OSI open source, whatever third-party lists claim. LangGraph Platform was renamed **LangSmith Deployment** (Oct 2025).

## Open-source orchestration frameworks

Libraries and frameworks you embed or self-host, where agents collaborate through crews, graphs, conversations, or role-play.

- [AgentScope](https://github.com/agentscope-ai/agentscope) — ✅ verified 2026-09-29. Multi-agent framework emphasizing agent teams and leader/worker coordination, planning, and human-agent interaction, with a visual multi-agent platform. Gotchas: Official repository README confirms Apache-2.0 license and describes agent teams, coordination, and planning as core capabilities.
- [Agno](https://github.com/agno-agi/agno) — ✅ verified 2026-09-29. Lightweight open-source framework and runtime for building agents, teams, and workflows for production agentic AI, with a runtime environment for serving them. Gotchas: Official repository (agno-agi org) opened; metadata and README confirm Apache-2.0; Formerly Phidata; Actively developed.
- [AutoGen](https://github.com/microsoft/autogen) — ✅ verified 2026-09-29. Microsoft Research framework for creating multi-agent AI applications that can act autonomously or work alongside humans; layered design with a Core API (message passing, event-driven agents, distributed runtime) and AgentChat (group chats, two-agent patterns), plus no-code AutoGen Studio. Gotchas: Official repository opened; legal notices state code is MIT (LICENSE-CODE), docs/content are CC-BY-4.0; In maintenance mode as of 2026; Microsoft directs new users to the Microsoft Agent Framework; Magentic-One (a multi-agent team for web/code/file tasks) is implemented in this repo rather than standalone.
- [CAMEL](https://github.com/camel-ai/camel) — ✅ verified 2026-09-29. Multi-agent framework supporting communicative agents, agent societies, role playing, task automation, code generation, communication, memory, and data generation/simulation. Gotchas: Official repository (camel-ai org) opened; repository metadata and README confirm Apache-2.0 license; Actively developed (~13k+ stars).
- [CrewAI](https://github.com/crewAIInc/crewAI) — ✅ verified 2026-09-29. Framework for building collaborative AI agent crews with defined roles, goals, and memory; Crews handle role-based collaboration while event-driven Flows enable more controlled, deterministic workflows. Gotchas: Official repository confirms MIT license and documents both Crews and Flows; Very active project (~35k+ stars); Official docs linked from the README: https://docs.crewai.com/.
- [Google Agent Development Kit (ADK)](https://github.com/google/adk-python) — ✅ verified 2026-09-29. Google's open-source agent development kit; code-first framework for building single agents and multi-agent systems with composition primitives such as sequential, parallel, and loop workflow agents plus sub-agent delegation. Gotchas: Python SDK; TypeScript and Go SDKs exist separately.
- [LangGraph](https://docs.langchain.com/oss/python/langgraph/overview) — ✅ verified 2026-09-29. Stateful orchestration layer for LangChain agents; models agents as nodes in a graph with durable execution, persistence, and streaming, supporting supervisor, sub-agent, and hierarchical multi-agent patterns. Gotchas: Official LangChain documentation; official README carries an MIT badge; The core multi-agent orchestration primitive in the LangChain ecosystem.
- [MetaGPT](https://github.com/FoundationAgents/MetaGPT) — ✅ verified 2026-09-29. Multi-agent framework implementing an SOP-driven 'software company' — role-based agents (product manager, architect, engineer, QA) collaborate to generate PRDs, designs, and code. Gotchas: Official repository (FoundationAgents org) confirmed MIT in repository search results; One of the pioneering role-based multi-agent frameworks.
- [OpenAI Agents SDK](https://github.com/openai/openai-agents-python) — ✅ verified 2026-09-29. Lightweight open-source Python library for building agentic apps; multi-agent workflows are expressed through handoffs and agents-as-tools, with built-in tracing and guardrails. Gotchas: Official OpenAI repository opened; README describes it as a lightweight yet powerful framework for multi-agent workflows, MIT licensed; Supersedes the experimental OpenAI Swarm.
- [PraisonAI](https://docs.praison.ai) — ✅ verified 2026-09-29. Production-oriented multi-agent framework with self-reflection and low-code orchestration of role-based agent crews. Gotchas: Official documentation site opened; MIT badge confirmed in the docs source; Main repo is mervinpraison/praisonaidocs (docs) with the framework under the PraisonAI org.
- [Semantic Kernel](https://github.com/microsoft/semantic-kernel) — ✅ verified 2026-09-29. Microsoft SDK for building AI agents and orchestrating agentic and multi-agent AI systems; lightweight open-source development kit that lets developers add agents and multi-agent orchestration to applications. Gotchas: Official Microsoft repository; README confirms MIT license and explicitly describes building and orchestrating multi-agent systems; Multi-language (Python, .NET, Java).
- [SmythOS Runtime Environment (SRE)](https://github.com/SmythOS/sre) — ✅ verified 2026-09-29. Open-source cloud-native runtime for agentic AI: runtime environment, SDK, and CLI for building, running, and managing agents locally, in cloud, or at the edge, with built-in security and 40+ production-ready components. Gotchas: Official repository (SmythOS org) opened; GitHub metadata confirms MIT license; Repository topics include multi-agent, multi-agent-systems, agent-framework, and orchestration; Newer project (created 2025-06-07, ~1.3k stars).

## Agent-to-agent protocols & standards

Protocols and specifications for agents to discover each other, delegate work, exchange messages, and transact.

- [A2A (Agent2Agent Protocol)](https://a2a-protocol.org) — ✅ verified 2026-09-29. Open protocol for peer-to-peer agent collaboration: agents publish an Agent Card at /.well-known/agent-card.json, then exchange tasks and messages over JSON-RPC 2.0, gRPC, or REST with SSE streaming and push notifications. Gotchas: Created by Google (Apr 2025), donated to the Linux Foundation / Agentic AI Foundation; v1.0.0 released 2026-03; IBM's ACP was merged into A2A (Aug 2025); Complementary to MCP (agent-to-agent vs agent-to-tool).
- [ACP (Agent Communication Protocol)](https://agentcommunicationprotocol.dev) — ✅ verified 2026-09-29. REST-native OpenAPI-defined protocol for agent-to-agent invocation: Agent Manifest discovery (GET /agents), runs (POST /runs) with sync/SSE/async modes, MIME-typed multipart messages, and trajectory metadata. Gotchas: Launched by IBM Research Mar 2025; merged into A2A under the Linux Foundation (Aug 2025); Reference repo i-am-bee/acp is archived — legacy/superseded, build on A2A instead.
- [Agent Protocol](https://agentprotocol.ai/) — ✅ verified 2026-09-29. Tech-agnostic OpenAPI specification defining a common REST interface for interacting with AI agents: create tasks (POST /ap/v1/agent/tasks), execute steps, and download/upload artifacts. Gotchas: See the official source for current details..
- [AGNTCY / OASF](https://schema.oasf.outshift.com/) — ✅ verified 2026-09-29. Cisco Outshift-initiated open collective (now Linux Foundation) building the 'Internet of Agents': OASF is a standardized schema for describing agent capabilities/identity/IO (modeled on OCSF), plus an Agent Directory, SLIM secure messaging, and identity specs. Gotchas: A stack of specs/SDKs rather than one wire protocol; positioned to complement A2A and MCP; Includes Agent Connect Protocol (ACP) for messaging and SLIM (MLS-based, quantum-safe) transports.
- [Agora](https://agoraprotocol.org) — ✅ verified 2026-09-29. Decentralized protocol for LLM-agent communication: agents default to natural language for rare exchanges, then negotiate and exchange self-generated protocol documents (hash-identified) to use efficient routines for frequent interactions. Gotchas: Originated from Oxford research; fully decentralized with no central registry; MIT-licensed per the official FAQ.
- [AITP (Agent Interaction & Transaction Protocol)](https://aitp.dev) — ✅ verified 2026-09-29. NEAR AI's open protocol for cross-trust-boundary interaction: agents communicate over Chat Threads (largely compatible with the OpenAI Assistants/Threads format) with extensible Capabilities for structured exchanges like payments, forms, and generative UI. Gotchas: Spec in progress; official docs show v0.1.0 Draft; Reference implementation target is agents on the NEAR AI Hub.
- [ANP (Agent Network Protocol)](https://agent-network-protocol.com) — ✅ verified 2026-09-29. Open protocol suite for the Agentic Web: did:wba decentralized identity, WNS human-readable handles, agent description and discovery documents, secure end-to-end messaging profiles, and application-layer protocols. Gotchas: Spec organized around the ANP 1.1 release line; the meta-protocol specification remains a draft; Governance is a small GitHub community; adoption is thin outside China.
- [AP2 (Agent Payments Protocol)](https://ap2-protocol.org/) — ✅ verified 2026-09-29. Google's open protocol for agent payment authorization: agents carry cryptographically signed mandates (Intent/Checkout/Payment Mandates as SD-JWT verifiable credentials) so every party can prove a purchase was authorized and audit it later. Gotchas: An authorization/audit layer, not a settlement rail; v0.2.0 (Apr 2026), standardization continuing in FIDO Alliance working groups; Originally an A2A AgentCard extension in v0.1; agent-to-agent delegation is out of scope in the current spec.
- [Coral Protocol](https://docs.coralos.ai/about) — ✅ verified 2026-09-29. MCP-native multi-agent coordination platform: agents join shared sessions over MCP, collaborate via @mention-addressed threads, and can be listed in a registry with Solana-based micropayments to agent developers. Gotchas: More platform + coordination pattern than neutral standard; graph-based multi-agent architecture (Anemoi) rather than hierarchical orchestration.
- [DIDComm](https://aca-py.org/1.0.1/gettingStarted/DIDcommMsgs/) — ✅ verified 2026-09-29. Hyperledger/Aries messaging layer for secure agent-to-agent communication: DID-based, end-to-end encrypted, asynchronous messages (transport-agnostic) with standard protocol sequences (DID exchange, credential issuance, present-proof) on top. Gotchas: Genuinely agent-oriented (Aries agents' messaging layer) but rooted in the self-sovereign-identity world; broader multi-agent ecosystem adoption is limited.
- [Eclipse LMOS Protocol](https://eclipse.dev/lmos/) — ✅ verified 2026-09-29. Eclipse Foundation protocol built on W3C Web of Things architecture: JSON-LD agent/tool descriptions signed with W3C DIDs, metadata propagation and discovery, transport-agnostic communication (lmosprotocol subprotocol), and DID/OAuth2 security schemes. Gotchas: Protocol text still work-in-progress (v1 namespace published); team signals intent to pursue W3C standardization; Eclipse project (EPL-typical licensing for Eclipse code, unverified).
- [FIPA-ACL / KQML](https://github.com/awebai/a2ac/blob/HEAD/projects/fipa-acl.md) — ⚠️ unverified. The original agent communication languages: KQML (DARPA, 1993) and FIPA-ACL (ratified 2000) standardized speech-act performatives (inform, request, propose, cfp) and interaction protocols like contract-net and subscribe/notify. Gotchas: Historic/legacy: formal semantics and ontology overhead limited adoption; FIPA became an IEEE Computer Society committee in 2005.
- [MCP (Model Context Protocol)](https://modelcontextprotocol.io) — ✅ verified 2026-09-29. Open standard (Anthropic, now under the Agentic AI Foundation) that standardizes how LLM applications connect to external tools, data sources, and prompts via JSON-RPC 2.0 in a client-host-server model. Gotchas: Current spec revision 2026-07-28 (stateless redesign).
- [NANDA](https://nanda.media.mit.edu/) — ✅ verified 2026-09-29. MIT Media Lab research infrastructure for the 'Internet of AI Agents': the NANDA Index (federated agent registry/name resolution), AgentFacts (capability documents signed as W3C Verifiable Credentials), and KYA third-party attestation. Gotchas: Discovery and trust layer, not a messaging wire protocol — it sits above MCP and A2A and does protocol translation via the NANDA Adapter.

## Workflow & orchestration infrastructure

Durable-execution and workflow engines with a real multi-agent story — the substrate long-running agent teams run on.

- [Activepieces](https://www.activepieces.com/pieces/ai) — ✅ verified 2026-09-29. Open-source (Community Edition MIT) visual AI-automation platform: native AI pieces incl. a 'Run Agent' action that reasons through multi-step tasks with tools, human-in-the-loop approval pieces, and 280+ pieces published as MCP servers usable directly by LLMs in Claude Desktop/Cursor/Windsurf. Gotchas: Community Edition is MIT; packages/ee/ (enterprise features) are under a separate Commercial License; Like n8n, more automation-platform than durable agent infra — included on the strength of the Run Agent action + MCP toolkit.
- [Camunda](https://github.com/camunda/camunda) — ✅ verified 2026-09-29. Enterprise process-orchestration platform (Zeebe engine) that added native agentic capabilities: GA'd AI Agent connector (8.8, Oct 2025) with ad-hoc sub-processes where the LLM dynamically picks BPMN activities, A2A client connectors, built-in MCP server, and ProcessOS agent intelligence layer (beta). Gotchas: Enterprise BPMN platform — heaviest fit in this list; engine is source-available under the Camunda License v1 (production requires Enterprise license), not OSS.
- [DBOS](https://docs.dbos.dev/) — ✅ verified 2026-09-29. Durable-execution library (Python/TypeScript/Go/Java) backed by Postgres: wrap any agent in DBOS workflows to checkpoint every LLM call and tool execution; first-party integrations for Vercel AI SDK (durableCalls middleware), OpenAI Agents SDK (DBOSRunner), Google ADK, and Pydantic AI. Gotchas: MIT across dbos-transact SDK repos; Lightweight approach: no separate orchestration cluster — durability lives in your app + Postgres; Official docs have a dedicated AI section (durable agents, parallelizing/scaling agents, HITL).
- [Hatchet](https://hatchet.run/) — ✅ verified 2026-09-29. Distributed, fault-tolerant task queue and DAG workflow engine backed by Postgres: named 'AI agents' as an official use case — define agentic workflows as code, retry failures, parallelize agent actions, with fair queuing, rate limits, durable sleeps/event waits, and OpenTelemetry. Gotchas: Fully MIT licensed end-to-end; self-hosted or Hatchet Cloud; Younger project (0.x as of Sept 2026, ~7.9k stars) with fewer production war stories than Temporal; load-tested to ~10k tasks/s.
- [Inngest](https://www.inngest.com) — ✅ verified 2026-09-29. Event-driven durable-execution platform for TypeScript/Python/Go: write step functions (step.run/step.invoke/step.sendEvent) that look like normal code while Inngest handles retries, state, sleeps and event waits; first-class agent patterns (sync/async/scheduled sub-agent delegation) and durable AI-agent primitives. Gotchas: Self-hostable since Jan 2026, but licensed under SSPL (not OSI open-source); Agent angle documented in Inngest's own blog ('durable AI agents', agentic patterns); Best DX of the durable-execution class; lighter-weight than Temporal.
- [LangSmith Deployment](https://docs.langchain.com/langsmith/deployment-quickstart) — ✅ verified 2026-09-29. LangChain's managed deployment for LangGraph multi-agent applications (renamed from LangGraph Platform, Oct 2025); the framework itself stays MIT open source. Gotchas: Renamed from LangGraph Platform to LangSmith Deployment in Oct 2025; Not full durable execution like Temporal — checkpointing + replay only.
- [n8n](https://n8n.io) — ✅ verified 2026-09-29. Fair-code visual workflow automation platform with mature AI capabilities: LangChain-based AI Agent nodes (Chat Trigger → AI Agent → chat model + memory + tools), human approvals, 1500+ integrations; self-hostable or n8n Cloud. Gotchas: Source-available under the Sustainable Use License (fair-code, not OSI open-source); More 'AI workflow automation' than durable multi-agent infra — no event-replay durability; HITL is webhook/Wait-node based; Included because its AI Agent nodes are real and widely used for agentic automation.
- [Orkes Conductor](https://orkes.io) — ✅ verified 2026-09-29. Open-source (Apache 2.0) event-driven agentic workflow engine, originally Netflix Conductor and maintained by Orkes: durable execution with native LLM task types (14+ providers), MCP tool calling, vector DB support for RAG, and human approval gates; scales to billions of executions. Gotchas: OSS engine (github.com/conductor-oss/conductor) + Orkes SaaS enterprise offering; Agent features are native task types (not bolt-on); Polyglot workers (Java/Python/Go/JS/C#/Ruby/Rust).
- [Prefect](https://docs.prefect.io/) — ✅ verified 2026-09-29. Python-native workflow orchestration (@flow/@task decorators, retries, caching, scheduling): widely used as the orchestration layer under AI agents and agentic coding pipelines — durable per-agent runs with task-level observability, often paired with frameworks like Pydantic AI. Gotchas: Core engine Apache-2.0 (note: /server directory is under the Prefect Community License).
- [Restack](https://www.restack.io/) — ✅ verified 2026-09-29. Enterprise AI agent platform and backend framework for building and deploying reliable AI agents: durable workflow orchestration, long-running agent execution, auto-generated REST APIs per agent/workflow, MCP tool exposure, Python/TypeScript SDKs on Kubernetes. Gotchas: Proprietary platform (enterprise tier); orchestration layer is built on Temporal under the hood; Primarily commercial — open-source examples and SDKs, but the core platform is not OSS.
- [Restate](https://docs.restate.dev/ai/patterns/durable-agents) — ✅ verified 2026-09-29. Open durable-execution foundation (Rust runtime + TS/Java/Python/Go/Kotlin SDKs) for building resilient agents: journals every step for crash recovery, durable promises for human-in-the-loop approvals, rollback/saga patterns for agents, and durableCalls middleware for Vercel AI SDK / LangChain / Pydantic AI. Gotchas: Runtime is BSL 1.1 source-available (not OSI open-source); SDKs are MIT; Dedicated AI docs (durable agents, HITL approvals, rollbacks); Runs as a server in front of your agent service — similar footprint to a message broker.
- [Temporal](https://temporal.io) — ✅ verified 2026-09-29. Open-source durable-execution workflow engine (workflows/activities/signals); a first-class runtime for long-running multi-agent systems — official OpenAI Agents SDK integration (temporalio.contrib.openai_agents), framework-agnostic multi-agent fleets (Google ADK + LangGraph on Temporal), and durable human-in-the-loop signals. Gotchas: Server is MIT (Go); SDKs vary; Agent integration evidence: official temporalio/sdk-python openai_agents plugin and Temporal's Aug 2026 multi-agent blog; Known pitfall from docs: separate task queues for slow LLM inference vs other activities to avoid starvation.
- [Trigger.dev](https://trigger.dev) — ✅ verified 2026-09-29. Open-source (Apache 2.0) developer platform for building AI agents and long-running durable workflows in TypeScript: no timeouts, durable checkpointing, automatic retries, queues/concurrency, human-in-the-loop waitpoints, tool calling/MCP support, and an MCP server for AI coding assistants. Gotchas: Originally a background-jobs framework (HN 2023); relaunched v3 in Sep 2025 with explicit AI-agent focus (YC W23, ~15.2k stars); Self-hostable via Docker Compose/Kubernetes or managed cloud.
- [Windmill](https://www.windmill.dev/) — ✅ verified 2026-09-29. Open-source developer platform/workflow engine that turns scripts (Python, TS, Go, Bash, SQL...) into workflows, webhooks and UIs: DAG flows with branching, retries, approval steps (human-in-the-loop), and a built-in MCP server that exposes workflows to AI agents. Gotchas: AGPLv3 core (copyleft — check implications for hosted use; some modules Apache-2.0); ~16k stars; Strong fit for script-centric agent tool execution, approval gates, and agent-triggered flows via MCP.

## Research papers & systems

Published papers and their accompanying systems on multi-agent collaboration, debate, and emergent behavior.

- [AgentLite](https://arxiv.org/abs/2402.15538) — ✅ verified 2026-09-29. Salesforce AI Research's lightweight library for building task-oriented LLM agents and experimenting with reasoning strategies and multi-agent architectures. Gotchas: Paper + repo (SalesforceAIResearch/AgentLite); using arXiv URL.
- [AgentVerse](https://arxiv.org/abs/2308.10848) — ✅ verified 2026-09-29. Multi-agent framework that dynamically recruits and adjusts agent team composition during task-solving, and studies emergent positive/negative social behaviors of agent groups (ICLR 2024). Gotchas: Paper + repo (OpenBMB/AgentVerse); using arXiv URL.
- [AutoAgents](https://arxiv.org/abs/2309.17288) — ✅ verified 2026-09-29. Automatically generates and coordinates a team of specialized agents adapted to the task at hand, with an observer role reflecting on plans and agent responses to improve coherence. Gotchas: Paper + repo (Link-AGI/AutoAgents); using arXiv URL.
- [AutoGen (paper)](https://arxiv.org/abs/2308.08155) — ✅ verified 2026-09-29. Microsoft framework for building LLM applications through multi-agent conversation: 'conversable agents' combine LLMs, tools, and human input orchestrated via conversation programming. Gotchas: Paper + repo (microsoft/autogen); using arXiv URL.
- [CAMEL: Communicative Agents](https://arxiv.org/abs/2303.17760) — ✅ verified 2026-09-29. Role-playing framework where two LLM agents (AI User and AI Assistant) autonomously cooperate via 'inception prompting' to complete complex tasks; foundational work on communicative agents (NeurIPS 2023). Gotchas: Paper + open-source repo (camel-ai/camel, Apache 2.0 for code); using arXiv URL.
- [ChatDev](https://arxiv.org/abs/2307.07924) — ✅ verified 2026-09-29. Virtual software company: role-playing agents (CEO, CTO, programmer, reviewer, tester) collaborate through a 'chat chain' with communicative dehallucination to build complete software (ACL 2024). Gotchas: Paper + repo (OpenBMB/ChatDev, Apache 2.0 code / CC BY-NC 4.0 data); using arXiv URL.
- [DyLAN](https://arxiv.org/abs/2310.02170) — ✅ verified 2026-09-29. Dynamic LLM-agent network: automatically selects an agent team from a candidate pool and deactivates underperforming agents mid-task via an LLM ranker, with early stopping for efficiency. Gotchas: Paper + repo (SALT-NLP/DyLAN); using arXiv URL.
- [Generative Agents](https://arxiv.org/abs/2304.03442) — ✅ verified 2026-09-29. Stanford 'Smallville' simulation: 25 memory-enabled LLM agents exhibit believable emergent social behavior (information diffusion, relationship formation) in a sandbox world (UIST 2023). Gotchas: A social simulation rather than a workflow framework; included for its multi-agent social-behavior relevance and influence on later multi-agent simulation work.
- [Magentic-One](https://arxiv.org/abs/2411.04468) — ✅ verified 2026-09-29. Microsoft Research's generalist multi-agent system: a lead Orchestrator plans, delegates to specialist agents (web browsing, file handling, coding), and recovers from errors across GAIA, AssistantBench, and WebArena. Gotchas: Research system with open-source implementation in microsoft/autogen; using arXiv URL.
- [MetaAgents](https://arxiv.org/abs/2310.06500) — ✅ verified 2026-09-29. Collaborative generative agents with human-like reasoning and specialized skills coordinate in a simulated job-fair environment to study team formation and task-oriented multi-agent coordination. Gotchas: Latest arXiv revision (2025) retitles it 'MetaAgents: Large Language Model Based Agents for Decision-Making on Teaming'; same paper, same ID.
- [MetaGPT (paper)](https://arxiv.org/abs/2308.00352) — ✅ verified 2026-09-29. Encodes human Standard Operating Procedures (SOPs) into multi-agent collaboration: specialized roles exchange structured artifacts via a shared message pool to build software (ICLR 2024 oral). Gotchas: Paper + repo (geekan/FoundationAgents MetaGPT, MIT); using arXiv URL.
- [Multiagent Debate](https://arxiv.org/abs/2305.14325) — ✅ verified 2026-09-29. Multiple LLM instances independently propose answers, then debate their reasoning over several rounds to converge on a more factual and better-reasoned final answer (ICML 2024). Gotchas: Founding paper of the multi-agent-debate sub-literature; the 'MultiAgent Debate (Du et al.)' entry merged here.

## Benchmarks & evals

Benchmarks that measure multi-agent collaboration, coordination, negotiation, and competition.

- [AucArena](https://arxiv.org/abs/2310.05746) — ✅ verified 2026-09-29. Evaluation suite simulating auctions where LLM bidding agents compete under budgets, benchmarking strategic planning and execution (budget management, goal adherence, adaptive strategy) in dynamic competitive multi-agent scenarios. Gotchas: Official suite name is 'AucArena' (paper: 'Put Your Money Where Your Mouth Is...'); third-party lists call it 'AuctionArena'.
- [BattleAgentBench](https://arxiv.org/abs/2408.15971) — ✅ verified 2026-09-29. Turn-based Battle City wargame benchmark with 7 sub-stages across 3 difficulty tiers that separately assess single-agent navigation, paired-agent task execution, and full multi-agent (2-team, 4-team, 8-agent) cooperation and competition. Gotchas: Tsinghua KEG, arXiv 2024; Level 1 is single-agent — multi-agent relevance is Levels 2–3.
- [Collab-Overcooked](https://arxiv.org/abs/2502.20073) — ✅ verified 2026-09-29. Two LLM agents cooperate via natural language in an extended Overcooked-AI kitchen across 30 open-ended tasks at 6 complexity levels, evaluated with process-oriented collaboration metrics (initiate vs. respond, trajectory efficiency). Gotchas: EMNLP 2025 Main; collaboration-focused (not competitive); open-source code at the repo linked in the paper.
- [GameEval](https://arxiv.org/abs/2308.10032) — ✅ verified 2026-09-29. Goal-driven conversational games (Ask-Guess, SpyFall, TofuKingdom) where LLM players take distinct roles with cooperative or adversarial objectives, probing cooperative/adversarial strategy, deception, multi-hop reasoning, and long-term planning. Gotchas: Code on GitHub is a third-party mirror (jordddan/gameeval); the paper's official code was released anonymously; license not confirmed.
- [LLM-Coordination (LLM-Co)](https://arxiv.org/abs/2310.03903) — ✅ verified 2026-09-29. Pure-coordination multi-agent benchmark: LLM agents act as proactive participants in four coordination games (Agentic Coordination), plus 198 multiple-choice CoordQA questions testing environment comprehension, Theory-of-Mind reasoning, and joint planning. Gotchas: UCSC, arXiv 2023 (v3 2025); code at github.com/eric-ai-lab/llm_coordination per the paper (license not confirmed).
- [MindAgent](https://arxiv.org/abs/2309.09971) — ✅ verified 2026-09-29. Gaming-interaction infrastructure for multi-agent planning and coordination, with the CUISINEWORLD benchmark dispatching an LLM coordinator and multiple agents to play simultaneously, scored by the CoS (collaboration efficiency) auto-metric. Gotchas: NAACL 2024 Findings; also covers human-NPC collaboration; code at github.com/mindagent/mindagent (license not confirmed).
- [MultiAgentBench](https://arxiv.org/abs/2503.01935) — ✅ verified 2026-09-29. Multi-agent-native benchmark on the MARBLE (Multi-Agent Coordination Backbone with LLM Engine) framework spanning 6 domains — research proposals, Minecraft building, coding, database error analysis (collaborative) plus Werewolf and bargaining (competitive) — with milestone-based KPIs comparing coordination topologies (star/chain/tree/graph). Gotchas: ACL 2025 (arXiv:2503.01935); original repo ulab-uiuc/MARBLE, also mirrored at MultiagentBench/MARBLE; repo license not confirmed.
- [SOTopia](https://github.com/sotopia-lab/sotopia) — ✅ verified 2026-09-29. Open-ended social-interaction environment where LLM agents role-play characters with private goals across 90 social scenarios (negotiation, collaboration, competition), scored on goal completion and 7 social dimensions via SOTopia-Eval. Gotchas: ICLR 2024 spotlight; dyadic by default, SOTopia-S4 extends to multi-party; requires LLM API key + Redis to run.

## Coordination, memory & state

Shared memory, message layers, checkpointing, and state tooling that agents use to coordinate.

- [AgentMail](https://www.agentmail.to/) — ✅ verified 2026-09-29. Email infrastructure built specifically for AI agents: programmatic inboxes (thousands of unique addresses via API), full send/receive, native threading, allowlists/blocklists, webhooks + WebSockets for event-driven agent communication. Gotchas: Commercial hosted product (official site agentmail.to; free tier with 3 inboxes); Coordination angle: gives each agent its own identity for async two-way messaging.
- [Cognee](https://github.com/topoteretes/cognee) — ✅ verified 2026-09-29. Open-source memory control plane for agents: an Extract-Cognify-Load pipeline builds a self-hosted typed knowledge graph (Kuzu/LanceDB/SQLite) plus vector + relational stores so agents share persistent long-term memory across sessions. Gotchas: Apache-2.0; Emphasizes cross-agent knowledge sharing, tenant isolation, traceability/audit; ~30k stars; Commercial Cognee Cloud tier exists.
- [Graphiti](https://github.com/getzep/graphiti) — ✅ verified 2026-09-29. Zep's open-source temporal knowledge-graph engine for AI agents: incrementally builds bi-temporal entity/fact graphs (Neo4j, FalkorDB, Neptune) with hybrid semantic + BM25 + graph-traversal retrieval, no LLM calls at query time. Gotchas: See the official source for current details..
- [LangGraph Checkpointing](https://docs.langchain.com/oss/python/langgraph/persistence) — ✅ verified 2026-09-29. Built-in state persistence for LangGraph agent workflows: a checkpointer snapshots full graph state after every super-step into threads (SQLite, Postgres, Redis, MongoDB), enabling pause/resume, time-travel debugging, and human-in-the-loop. Gotchas: Not a standalone repo — a LangGraph feature (LangGraph itself is MIT); Companion BaseStore provides cross-thread shared memory (PostgreSQL/Redis/in-memory) used by LangMem.
- [LangMem](https://github.com/langchain-ai/langmem) — ✅ verified 2026-09-29. LangChain's official long-term memory SDK for LangGraph agents: extracts and consolidates semantic, episodic, and procedural memories (incl. self-improving system-prompt optimization) backed by LangGraph's BaseStore. Gotchas: MIT; Extraction/consolidation layer over LangGraph storage, not a standalone DB; namespace isolation for multi-tenant memory; agent-facing manage/search memory tools.
- [Letta](https://github.com/letta-ai/letta) — ✅ verified 2026-09-29. Platform for stateful AI agents with self-improving memory (formerly MemGPT, from the UC Berkeley research project): OS-inspired hierarchical memory (core blocks + archival recall) so agents persist and compound knowledge across sessions. Gotchas: Apache-2.0 confirmed via GitHub repo metadata.
- [Mem0](https://github.com/mem0ai/mem0) — ✅ verified 2026-09-29. Universal memory layer for AI agents: extracts facts from conversations into user/agent/session-scoped long-term memory with hybrid semantic + keyword + entity retrieval; the standard drop-in memory API for multi-agent apps. Gotchas: Apache-2.0 OSS repo plus managed Mem0 Platform (commercial); Self-hostable with 20+ vector-store backends; optional graph backends (Neo4j, Memgraph, Kuzu).
- [Redis Agent Memory](https://github.com/redis/agent-memory-server) — ✅ verified 2026-09-29. Redis's managed memory layer for AI agents (part of Redis Iris, their real-time context engine): two-tier model with session memory (configurable TTL) and background promotion of extracted facts to long-term vector-backed memory. Gotchas: Apache License 2.0 per official README on the repo (opened 2026-09-29); Repo is the research/open foundation; the production distribution is Redis Agent Memory in Iris via Redis Cloud; Ships MCP server interface.
- [SuperMemory](https://github.com/supermemoryai/supermemory) — ✅ verified 2026-09-29. Memory and context engine + API for the AI era: embeddings-based hybrid RAG + fact memory + evolving user profiles, with a hosted platform and a self-hostable local binary. Gotchas: MIT (repo LICENSE); Cloud-first with self-host local binary; official plugins for Claude Code, Cursor, Codex, OpenCode, OpenClaw + MCP server at mcp.supermemory.ai/mcp; Note: v0.0.7+ release notes mention a 10,000-document cap on self-hosted ('supermemory lite').
- [Zep](https://www.getzep.com) — ✅ verified 2026-09-29. Commercial agent-memory platform that stores agent memory as temporal knowledge graphs — facts carry validity intervals so agents track what was true vs. what is true now. Gotchas: Managed product (Zep Cloud) is commercial/closed; open-source Community Edition deprecated April 2025 in favor of Graphiti; Treat acquisition claim as unconfirmed.
